# ЛР7 · Етап 1 — фінальний сценарій

**Користувач:** людина, яка веде особистий бюджет і не хоче вручну обирати категорію для кожної витрати.
**Задача:** швидко записати операцію звичайним текстом і бачити, скільки бюджету місяця лишилось.
**Вхід:** опис операції довільним текстом (2–200 символів), напр. «Кава в Aroma Kava 85 грн», «Епіцентр 640 грн».
**Результат:** категорія, сума, валюта, магазин і пояснення від AI; за потреби — виправлення категорії.
**Подальша дія:** «Зберегти» → операція потрапляє в історію (Room) і перераховує «Бюджет місяця»; виправлення враховуються в наступних розпізнаваннях.

## Основний шлях
Введення → валідація на пристрої (`InputValidator`) → `CategorizeTransactionUseCase` (+ виправлення з Room) → `POST /api/v1/transactions/categorize` → Pydantic-валідація → `parse` (сума/валюта/магазин) → `classifier.predict` + `personalizer` → JSON → mapper → картка результату → «Зберегти» → Room → бюджет (`POST /api/v1/budget/summary`) → історія.

## Критерії роботи системи
| # | Критерій |
|---|---|
| C1 | «Кава в Aroma Kava 85 грн» → «Кава», 85 ₴, Aroma Kava, пояснення; «Зберегти» додає операцію в історію й бюджет без ручного редагування даних |
| C2 | Після виправлення «Епіцентр → Житло» наступний «Епіцентр 640 грн» розпізнається як «Житло» з позначкою персоналізації |
| C3 | Некоректне введення не надсилається; збій сервера чи мережі показує зрозуміле повідомлення й «Повторити», застосунок не падає й не зависає (тайм-аути 5/10 с) |
| C4 | Невпевнений результат відрізняється від помилки: «Інше» + вибір категорії, а не картка помилки |
| C5 | Дані (історія, збережені операції) лишаються після перезапуску; повтор після помилки працює без перезапуску |

## Поведінка інтерфейсу
| Ситуація | Поведінка |
|---|---|
| Початковий стан | підказка з прикладами; кнопка «Розпізнати» неактивна, поки поле порожнє |
| Обробка | картка завантаження; кнопка неактивна (`canSubmit = false`) — повторне натискання не створює другого запиту; новий `submit()` скасовує попередній запит |
| Успіх | картка результату: категорія, сума, впевненість/схожість, пояснення, вибір категорії, «Зберегти» / «Скасувати» |
| Немає придатного результату | «Інше» + «Оберіть категорію», «Зберегти» неактивна до вибору (не помилка) |
| Технічна помилка | картка помилки з причиною (немає з'єднання / тайм-аут / сервер / незрозуміла відповідь / щось пішло не так) + «Повторити»; для мережі — «Зберегти запит і надіслати пізніше» |
| Невірне введення | текст під полем, запит не йде; дія — виправити введення |
| Повернення з фону | стан у `ViewModel` (`StateFlow`) зберігається; запит, що виконувався, завершується у `viewModelScope`; поточний екран зберігає `rememberSaveable`. Якщо система вивантажила процес — введений текст губиться, але історія й операції в Room лишаються |
| Повторне надсилання «очікує» | атомарний `UPDATE … WHERE status='PENDING'` — другий запит не надсилається |
| Дозволи | застосунок використовує лише `INTERNET` — звичайний дозвіл, що надається при встановленні; runtime-запитів немає, тому сценарію «відмова в дозволі» немає (заміна в `functional-tests.md`) |
| Stack trace / тексти SDK | не показуються: `safeApiCall` перетворює винятки на `AppError` з українським текстом |

# AI instructions (для coding agent)

Ти працюєш з репозиторієм AuraWallet-Android: `mobile/` (Kotlin, Compose), `backend/` (FastAPI, scikit-learn), `docs/` (Knowledge Base).

## Порядок роботи
1. Прочитай `docs/` (щонайменше `architecture.md`, `api-contract.md`, `known-limitations.md`) і перевір структуру репозиторію (`git ls-files`).
2. Спочатку поясни, як зараз працює релевантна частина, і запропонуй план: кроки, критерії готовності, **список файлів**, які зміниш.
3. Чекай підтвердження плану. Реалізуй **один крок** за раз.
4. Після кроку: покажи `git diff --stat`, запусти перевірки (`pytest -q`, `./gradlew test`), опиши результат.
5. Кожен перевірений крок — окремий commit з повідомленням у форматі `type(scope): що зроблено`.
6. Наприкінці онови `docs/` і README під фактичний код.

## Обмеження
- Не переписуй проєкт і не роби рефакторинг поза задачею.
- Не змінюй API-контракт без пояснення; якщо змінюєш — онови `api-contract.md`, `schemas.py` і `ApiModels.kt` в одному кроці. Додавати нові поля у відповідь можна, видаляти/перейменовувати — ні.
- Не додавай залежності без обґрунтування (навіщо, розмір, альтернатива).
- Не зберігай секрети в коді, prompts або Git. Тестові дані — лише синтетичні, без реальних карток, токенів, виписок.
- Не ламай сценарій ЛР2 (`docs/testing.md`, M1–M6).
- Додавай або оновлюй тести для нової поведінки (backend — pytest, mobile — JVM unit-тести).
- Повідомлення для користувача — українською; помилки без технічних деталей.
- Дотримуйся рішень з `decisions.md`; щоб змінити рішення — допиши новий рядок з причиною.

## Підсумок після задачі
Що змінено (файли), як перевірено (команди + результат), які ризики й обмеження лишились, що оновлено в `docs/`.

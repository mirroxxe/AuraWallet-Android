# AI component

## Призначення
Визначити категорію операції з короткого опису й пояснити вибір. Сума, валюта й магазин виділяються правилами (не AI).

## Модель
- `sklearn.Pipeline`: `FeatureUnion(TF-IDF char_wb 2–5, TF-IDF word 1–2)` → `LogisticRegression(C=12)`.
- Дані: `backend/app/ai/training_data.csv`, 201 вигаданий приклад, 17 категорій (uk + en).
- Навчається при старті сервісу (~0,1–0,2 с), зберігається в пам'яті; файлу моделі немає.
- Працює офлайн, без ключів і зовнішніх API.

## Вхід / вихід
- Вхід: `cleaned_text` — опис без суми й валюти (від `parser.parse`).
- Вихід (`Prediction`): `category`, `confidence`, `alternatives` (топ-3), `keywords` (слова з найбільшою позитивною вагою для класу, без службових слів).

## Пояснення
`service._explain()` формує текст: «Схоже на «Кава» (95%) на основі ключових слів «кава», «aroma kava». Магазин: Aroma Kava.»

## Обмеження
- Малий синтетичний датасет: нові магазини й рідкісні формулювання → низька впевненість (напр. «квиток на потяг» 0,29).
- Не розуміє контексту довгих речень і заперечень.
- Сума без валюти вважається гривнями; з кількох чисел без валюти береться останнє.
- Пояснення — ваги слів, а не причинно-наслідкове міркування.

## Fallback
| Ситуація | Поведінка |
|---|---|
| `confidence < AI_MIN_CONFIDENCE` (0,30) | `category = other`, `low_confidence = true`, альтернативи; mobile просить обрати вручну і блокує «Зберегти», поки не обрано |
| модель не завантажилась / виняток у `predict` | 503 `ai_unavailable`; mobile показує повідомлення й «Повторити» |
| `AI_SIMULATE_FAILURE=true` | штучний 503 для тестування |

## Як змінювати
Додати приклади в `training_data.csv` (формат `text,category`), перезапустити сервер, прогнати `pytest -q` і таблицю прикладів з README.
